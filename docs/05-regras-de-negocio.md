# Regras de negócio — ConectaGlobal

As regras abaixo separam princípios de domínio descritos na documentação-base e regras propostas para operacionalizar o sistema. Regras acadêmicas específicas de editais devem ser configuradas por oportunidade, não generalizadas para todos os programas.

## 1. Regras gerais do domínio

| ID | Regra |
|---|---|
| RN-01 | Cada oportunidade deve possuir identificação, descrição, modalidade, destino, prazo e responsável pela atualização. |
| RN-02 | Os critérios de elegibilidade devem estar associados à oportunidade correspondente. |
| RN-03 | Requisitos acadêmicos, linguísticos e documentais podem variar conforme edital ou instituição parceira. |
| RN-04 | A autoavaliação do estudante possui caráter orientativo e não substitui a análise da candidatura. |
| RN-05 | A manifestação de interesse ou candidatura deve estar vinculada a uma oportunidade publicada. |
| RN-06 | O estudante deve ser informado sobre documentos e pendências exigidos para a candidatura. |
| RN-07 | A candidatura deve possuir status e histórico de alterações. |
| RN-08 | A publicação, suspensão e encerramento de oportunidades são operações restritas à equipe do NEI ou perfil autorizado. |
| RN-09 | O sistema deve impedir o envio de candidatura após o prazo, salvo se a oportunidade admitir exceção configurada por usuário autorizado. |
| RN-10 | A alteração de status deve registrar data, responsável e situação resultante. |
| RN-11 | A aprovação interna ou indicação não garante aceitação pela instituição de destino, quando houver etapa externa de admissão. |
| RN-12 | Relatos e interações colaborativas devem respeitar regras de privacidade e moderação. |

## 2. Regras de gestão e acesso

| ID | Regra |
|---|---|
| RN-13 | Cada usuário acessa somente funcionalidades permitidas ao seu perfil. |
| RN-14 | Apenas usuários autorizados podem criar ou alterar convênios, oportunidades, bolsas e parâmetros de elegibilidade. |
| RN-15 | Dados e documentos de candidatura devem ser acessíveis somente a usuários autorizados e ao próprio candidato, conforme política de acesso. |
| RN-16 | Relatórios devem respeitar permissões e não expor dados pessoais desnecessários. |
| RN-17 | Notificações devem ser geradas a partir de eventos relevantes, como prazo próximo, pendência ou mudança de status. |

## 3. Pontos a detalhar na P2
- Estados possíveis da candidatura e transições válidas.
- Prazos de alerta e canais de notificação.
- Campos e documentos obrigatórios por modalidade.
- Regras de moderação do fórum e dos relatos.
- Política de retenção de documentos e dados pessoais.
- Critérios de geração e acesso aos relatórios.
